# 섯다라인 서버 주간 기능 소개 (기획·미구현)

> 상태: 기획, 구현 대기. 소개 문구는 초안(애드온 "이럴 때 좋아요"는 제작자 다듬기).
> 기준 코드: 디스코드봇 `main` `b7c5417`, 애드온 `StarlineBot/mabinogi_addon` `833b388`(v0.45.0)

## 1. 목적

섯다라인 디스코드봇·애드온의 설명·아이디어 제안·배포용 디스코드 서버(이하 섯다라인 서버)에서, 매주 기능을 하나씩 "혹시 이 기능 써 보셨나요?" 형식으로 소개한다.

- 오래 쓴 사용자도 몰랐던 기능을 발견하게 한다.
- 소개 글 끝에 의견 경로를 붙여 자연스럽게 제안을 받는다.
- **개인 정보 없음**: 누가 무엇을 설정·제안했는지는 다루지 않는다(공개를 원하지 않는 사람이 많음).

## 2. 형식

### 메시지 2개: 디스코드봇 / 애드온
매주 같은 시각에 **디스코드봇 소개 1개 + 애드온 소개 1개**를 각각 별도 메시지로 올린다.
- 사용자층이 다르므로(봇은 서버 단위, 애드온은 PC 개인 프로그램) 메시지를 분리해 각자 관심 있는 쪽만 보게 한다.
- 반응 이모지도 메시지별로 따로 집계돼 봇/애드온 기능 인지도를 따로 볼 수 있다.

### 메시지 틀

```
💡 혹시 이 기능 써 보셨나요?  [🤖 디스코드봇 | 🖥️ 애드온]

<이모지> <기능 이름>
<무엇을 하는지 1~2줄>

👍 이럴 때 좋아요
<실제 상황 1줄>

▶ 써 보기: <명령어 또는 애드온 메뉴 위치>

써 봤어요 👍 · 처음 알았어요 🆕
의견·불편한 점은 #아이디어 에, 공개가 부담되면 봇 DM으로 편하게 보내 주세요.
```

- 임베드 1장. 봇/애드온은 임베드 색과 머리말(🤖/🖥️)로 구분.
- 결과가 이미지인 기능(`/요리`, `/주간일정`, 애드온 오버레이 등)은 예시 이미지 첨부(선택).
- 봇이 게시 직후 👍 🆕 반응을 미리 달아 둔다(누르기 쉽게). 🆕가 많은 기능 = 덜 알려진 기능 → 설명·이름 개선 후보.
- 애드온 의견 경로는 애드온의 **문의하기**(웹훅 → 모드메일)도 함께 안내 가능.

## 3. 고르는 방식 — 셔플 백

봇·애드온 **각각 별도 목록**에서 고른다.
- 목록을 섞어 순서를 정하고 매주 하나씩 꺼낸다. 다 쓰면 다시 섞는다.
  → 모든 기능이 한 번씩 나오고, 한 바퀴 안에서는 겹치지 않는다.
- 다시 섞을 때 직전 바퀴의 마지막 항목이 첫 항목으로 오지 않게 한다(연속 중복 방지).
- 목록 규모: 봇 약 29개, 애드온 약 26개 → 주 1회 기준 각 반년 이상.

## 4. 운영 — 봇 자동 게시

- **게시**: `events/ready/cronJob.js`에 주 1회 잡. 예: 수요일 19시대 KST(정각 피함). `luxon` `Asia/Seoul`.
- **채널**: `config/bot.js`에 `spotlightChannelId`(섯다라인 서버의 소개/공지 채널) 추가. 비어 있으면 off.
- **공지 채널이면 게시 처리**: 공지(Announcement) 채널은 올린 뒤 `message.crosspost()`까지 해야 팔로우한 다른 서버로 전달된다.
- **상태 저장**: `static/json/spotlight.json` — `{ bot: { order: [...], index }, addon: { order: [...], index }, lastPostedAt }`. `readAll/writeAll` 관례, 없으면 `{}`. 재기동돼도 이어서 진행, 같은 주 중복 게시 방지(`lastPostedAt`).
- **소개 글 목록**: `modules/featureSpotlight.js`(사람이 쓰는 문구 데이터). 항목: `{ id, target: 'bot'|'addon', emoji, name, what, when, tryIt, image? }`.
  - 봇 목록에서 비활성(`deleted:true`)·베타(`beta:true` 또는 설명에 [BETA]) 명령은 `/섯다라인`처럼 제외 — 목록에 넣더라도 게시 시점에 다시 걸러 낸다.
  - 설정 기능 문구는 설정 안내 기획(`docs/onboarding-guide-plan.md`)의 기능 카탈로그와 맞춘다.
- **development**: 매분 대신 테스트 서버 채널로만 게시(실서버 채널 금지).
- **제작자 확인용(선택)**: `!소개 미리보기`(다음 주 소개 2개를 제작자 DM으로), `!소개 건너뛰기`(이번 항목 패스) — 기존 `!메세지삭제` 같은 접두사 텍스트 명령, `developerId` + 테스트 서버에서만.

## 5. 아이디어 포럼 태그 연동

섯다라인 서버의 **아이디어 제안 포럼**은 아이디어마다 글 하나, 상태를 태그로 관리한다(태그: ✅적용됨 · ✉️접수 · 📝작업중 · ⚠️보류 · 🛠️베타 · ⛏️알파). 이 태그를 주간 게시물의 소재로 쓴다.

### 태그 → 게시물 종류

| 포럼 태그 | 게시물 | 문구 방향 |
|---|---|---|
| ✉️접수 (아이디어를 받아 기획하는 단계) | 💭 **고민 중** | "이런 걸 고민하고 있어요 — 어떻게 생각하세요?" 수요·세부 의견 수집 |
| 📝작업중 | 🔨 **만드는 중** | "지금 이런 걸 만들고 있어요" + 개발 근황 한 줄 |
| ⛏️알파 (제작자 테스트 단계) | 🔨 **만드는 중** | 위와 같음 + "테스트 중인데 생각대로 동작을 안 하네요" 같은 웃긴 근황 한 줄 |
| ✅적용됨 + 🛠️베타 | 🛠️ **베타 피드백** | "혹시 이 기능 써 보셨나요? 써 보신 분들 어떠셨어요?" |
| ✅적용됨(베타 아님) | 💡 **기능 소개** 후보 | 일반 소개 목록(§7·§8)에 없으면 추가 후보로 제작자에게 알림 |
| ⚠️보류 | 게시 안 함 | |

단계 흐름: 접수(💭 고민 중) → 작업중·알파(🔨 만드는 중) → 적용됨+베타(🛠️ 베타 피드백) → 적용됨(💡 기능 소개).

### 주간 슬롯 우선순위(메시지 수는 주 2개 유지: 🤖봇 1 · 🖥️애드온 1)
각 슬롯마다 아래 순서로 **아직 소개 안 한 것** 하나를 고른다.
1. 🛠️ 베타 피드백 — 새로 베타로 적용된 기능(피드백이 가장 급함)
2. 🔨 만드는 중 — 알파 → 작업중 순(출시에 가까운 것 먼저)
3. 💭 고민 중 — 접수
4. 💡 기능 소개 — 셔플 백(§3)

→ 소식이 있는 주엔 소식이, 없는 주엔 기능 소개가 나간다. 게시물 수가 늘지 않아 피로도 유지.

### 봇/애드온 구분
현재 태그는 상태만 있어 아이디어가 봇용인지 애드온용인지 알 수 없다 → 포럼에 **🤖디스코드봇 / 🖥️애드온 태그 추가**(디스코드 포럼 태그는 채널당 20개까지, 글마다 여러 개 가능). 대상 태그가 없는 글은 게시 대상에서 제외하고 미리보기에서 알려준다.

### 같은 아이디어 반복 방지
`spotlight.json`에 `featured: { [threadId]: '고민중' | '만드는중' | '베타' }` 기록. **같은 단계로는 한 번만** 소개하고, 태그가 바뀌면(접수 → 작업중 → 적용됨+베타) 새 단계로 다시 소개할 수 있다 → "고민 중이던 그 기능, 만들기 시작했어요" → "베타로 나왔어요" 흐름. 작업중 → 알파는 같은 "만드는 중" 단계라 다시 소개하지 않는다.

### 게시물 문구
의견은 **포럼의 그 아이디어 글로 모은다**: 게시물에 해당 글 링크를 걸어 댓글이 아이디어 글에 쌓이게 한다. 작성자는 표시하지 않는다(개인 정보 없음 원칙).

```
💭 이런 걸 고민하고 있어요  [🖥️ 애드온 · ✉️접수]

완전자동찾기
기능마다 따로 지정하던 화면 위치를, 앱이 화면을 보고 알아서 찾아요.
안 보이면 보일 때 다시 찾고요.

어떻게 생각하세요? 필요한지, 이런 점이 있으면 좋겠다 등
→ 💬 아이디어 글에 남기기 (링크)
```

```
🔨 지금 이런 걸 만들고 있어요  [🖥️ 애드온 · ⛏️알파]

완전자동찾기
기능마다 따로 지정하던 화면 위치를, 앱이 화면을 보고 알아서 찾아요.

📓 개발 근황: 알파 만들어서 테스트 중인데… 생각대로 동작을 안 하네요 🙃

이런 점은 꼭 됐으면 좋겠다 싶은 게 있으면
→ 💬 아이디어 글에 남기기 (링크)
```

```
🛠️ 혹시 이 기능 써 보셨나요? (베타)  [🖥️ 애드온]

서버별 채널 상태
서버별 채널 상태를 보고 가장 빠른 채널을 알려줘요.

써 보신 분들 어떠셨어요? 불편한 점·잘 안 맞는 점
→ 💬 아이디어 글에 남기기 (링크) · 공개가 부담되면 봇 DM
잘 쓰고 있어요 👍 · 아쉬워요 🤔
```

### 소개 문구 출처
포럼 글 본문은 제작자 메모("기능별로 자동찾기가 있지만 • 그냥 앱이 …")라 그대로 쓰기 어렵다.
- 기본: 글 **제목** + 본문 요약을 초안으로 쓰되, 글 안에 제작자가 `소개:`로 시작하는 댓글을 달면 그 문장을 우선 사용.
- 🔨 만드는 중의 **개발 근황**: 글에 제작자가 `근황:`으로 시작하는 댓글을 달면(가장 최근 것) 그 문장을 사용. 없으면 아래 근황 문구 모음에서 고른다.

### 개발 근황 문구 모음 (가볍고 웃기게)
단계별로 모아 두고 셔플 백으로 돌려 같은 문구가 연달아 나오지 않게 한다. 실제 상황과 무관한 농담이므로 `근황:` 댓글이 있으면 항상 그쪽이 우선.

⛏️ 알파(제작자 테스트)
- 알파 만들어서 테스트 중인데… 생각대로 동작을 안 하네요 🙃
- 제 컴퓨터에선 잘 되는데요… (개발자 국룰)
- 버그 하나 고쳤더니 버그 두 개가 인사하네요 👋
- 테스트하러 들어갔다가 보스한테 맞고 테스트를 못 했어요
- 거의 다 됐어요. (개발자의 "거의"는 믿으시면 안 됩니다)

📝 작업중
- 설계는 끝났고 이제 코드랑 싸우는 중입니다 ⚔️
- 커피 줄어드는 속도로 진행도를 가늠해 주세요 ☕
- 만들다 보니 처음 생각보다 커졌어요. 언제나 그렇듯이요

✉️ 접수(고민 중)
- 아직 머릿속에만 있어요. 여러분 의견에 따라 모양이 바뀔 수 있어요
- 만들지 말지부터 고민 중이에요. 필요하신 분 손 🙋

🛠️ 베타
- 잘 되는 것 같은데… 여러분 컴퓨터에서도 잘 되는지 궁금해요
- 게시 하루 전(예: 화요일 저녁) 제작자에게 **미리보기 DM**(이번 주 2개 + `건너뛰기` 버튼) → 문구 손볼 시간 확보.

### 구현 메모
- `config/bot.js`에 `ideaForumChannelId` 추가. 봇에 포럼 보기 권한 필요.
- 포럼 글 조회: 활성 스레드 + 보관된(archived) 스레드 모두(`threads.fetchActive()`·`fetchArchived()`). 태그는 ID로 붙어 있으므로 포럼의 `availableTags`로 이름 매핑.
- 태그는 **이름으로** 매칭(이모지 제외). 태그 이름을 바꾸면 매핑도 바꿔야 함 → 매핑 표를 한 곳(상수)에 둔다.

## 6. 아이디어 상태 변경 알림 (실시간)

주간 게시와 별개로, 아이디어 포럼 글의 **상태 태그가 바뀌는 즉시** 알림 채널에 한 줄 소식을 올린다. 같은 포럼 인프라(§5)를 공유하므로 이것부터 만들면 주간 게시의 기반도 같이 생긴다.

### 메시지

```
📝 아이디어 상태가 바뀌었어요  [🖥️ 애드온]
완전자동찾기 — 홍길동 님 제안
✉️접수 → 📝작업중
💬 아이디어 글 보기 (링크)
```

- 태그가 여러 개 동시에 바뀌면 한 줄로: `📝작업중 → ✅적용됨 · 🛠️베타`
- 새 글이 올라오면: `✉️ 새 아이디어가 접수됐어요 — <제목>`(접수 태그가 붙은 시점 기준)
- 작성자: 이름만 표시(@멘션으로 호출하지 않음). 포럼에서 이미 공개된 정보 범위. 제작자 본인이 올린 글은 "— ○○ 님 제안" 생략.
- (선택) 제안자에게 DM: "제안하신 '<제목>'이 📝작업중으로 바뀌었어요" — 제작자 본인 글 제외.

### 동작 규칙
- **상태 태그만** 본다(접수·작업중·알파·베타·적용됨·보류). 대상 태그(🤖디스코드봇·🖥️애드온)나 제목 변경은 무시.
- **잠깐 기다렸다 올리기(2분)**: 태그를 여러 번 고치는 중일 수 있으므로, 마지막 변경 후 2분 동안 추가 변경이 없을 때 최종 상태로 한 번만 올린다. 2분 안에 원래 상태로 되돌리면 올리지 않는다.
- **비교 기준은 저장된 마지막 상태**: discord.js의 `threadUpdate`가 주는 이전 상태(oldThread)는 봇 재시작 후나 보관(archived)된 글에선 비어 있을 수 있다 → `static/json/ideaForumState.json`에 `{ [threadId]: [상태 태그 이름...] }`를 저장해 두고 그것과 비교. 기동 시 포럼 글을 한 번 읽어 저장값이 없는 글은 **알림 없이** 현재 상태로 초기화(재시작 때 알림 폭탄 방지).

### 구현 메모
- 이벤트: `events/threadUpdate/ideaStatusAlert.js`(신규 폴더), 새 글은 `events/threadCreate/`에 핸들러 추가. 이미 켜진 `GatewayIntentBits.Guilds`로 스레드 이벤트를 받으므로 인텐트 추가 불필요.
- 핸들러는 `thread.client` 사용(`events/threadCreate/inquiryLink.js`와 같은 패턴 — djs-commander 인자 위치 의존 회피).
- `thread.parentId === ideaForumChannelId`인 글만. 태그 ID → 이름은 포럼 `availableTags`로 매핑(§5 매핑 상수 공유).
- `config/bot.js`: `ideaForumChannelId`(§5와 공유), `ideaStatusChannelId`(알림 채널). 비어 있으면 off.
- 저장 파일은 주간 게시의 `featured` 판단에도 재사용 가능.
