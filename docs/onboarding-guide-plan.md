# 설정 기능 1회 안내 + 파티 기능 정리 + 게임서버 설정 (기획 확정·미구현)

> 상태: 기획, 구현 대기. "기본안"으로 표시된 항목은 구현 전 최종 확인. 섹션 배치·문구는 개발·테스트하며 조정.
> 기준 코드: `main` `c320f39`

## 1. 배경

- 봇이 새 서버에 들어가면(`events/guildCreate/registerNewGuild.js`) **제작자에게만** 설치 DM이 가고, 서버장에게는 아무 안내가 없다.
- `/섯다라인설정`의 기능은 **기본이 전부 꺼짐**이고 관리자만 켤 수 있다. 서버장이 모르면 길드원 눈엔 존재 자체가 안 보인다.
  → 기능을 "안 쓴다"기보다 "켜야 하는 줄 모른다"에 가깝다.
- 서버장 신원(`guild.ownerId`, `guildRegistry.json`)과 기능 on/off(`guildSettings.json`)가 이미 있어 대상·상태 판별이 가능하다.
- 일반 명령어(`/오미`, `/요리` 등)는 설치 즉시 동작하고 `/`나 `/섯다라인`(명령어 목록 자동 생성)으로 스스로 발견된다 → 안내 대상 아님.

## 2. 원칙

- **안내 대상은 설정 기능(`/섯다라인설정`)만.**
- **서버당 딱 1회 발송, 반복·리마인드 없음.** 한 번 보낸 서버엔 다시 보내지 않는다(1회뿐이라 수신거부 버튼도 없음).
- 설정 기능 전체를 섹션별로 한 번에 제대로 안내한다.

이유: 서버장은 DM 수신에 동의한 적이 없어 반복 DM은 광고로 느껴지고, 봇 계정이 스팸 신고·탐지 대상이 되면 전체 서버의 봇이 함께 멈출 수 있다.

## 3. 발송 대상과 시점

| 대상 | 시점 | 받는 곳 | 내용 |
|---|---|---|---|
| **신규 설치 서버** | 설치 직후 자동 1회 | 서버장 DM → 실패 시 서버 시스템 채널 | §4 섹션별 전체 안내 |
| **기존 설치 서버** | 기획 확정·배포 후, **제작자가 직접 실행해 딱 1회** | 서버장 DM → 실패 시 서버 시스템 채널 | §4 섹션별 전체 안내 + **이미 켠 기능 ✅ 표시** |

- 현재 설치 서버에서 봇이 빠진 곳이 없으므로 기존 서버 전체가 대상.
- 기존 서버 발송은 자동(봇 기동 시)이 아니라 **수동 트리거**(§7). "확정되면 그때 한 번"을 그대로 구현하고, 기동할 때마다 조건을 검사하다 잘못 발송되는 사고를 원천 차단한다.
- 기능을 이미 켠 서버에도 보내되, 켜 둔 기능은 ✅로 구분하고 설정 예시를 생략해 "이미 쓰는 기능 + 아직 안 쓰는 기능"을 한눈에 보여준다.
- DM 실패 시 시스템 채널 대체도 서버당 1회뿐이라 허용. 시스템 채널이 없거나 권한이 없으면 실패로 기록하고 끝.

## 5. 파티 기능 2종 정리

### 이름: 현행 유지
- `/파티모집`(명령)·`파티모집`(설정)은 사람이 직접 쓰는 명령으로 명확하고 짧다.
- `인게임파티모집현황`은 길지만 "게임 안의 모집 현황"이라는 의미가 그대로 드러난다.
- 대안으로 검토한 `길드파티모집`은 "길드"가 디스코드 서버인지 게임 길드인지 불명확, `거뿔파티중계`는 약어를 알아야 이해됨 → 채택 안 함.
- **이름은 그대로 두고 설명 문구와 나란히 비교로 혼동을 해소**한다. 이름 변경이 없으므로 기존 사용자 공지·마이그레이션 불필요.

### 현재 차이

| | 파티모집 (`partyRecruitEnabled`) | 인게임파티모집현황 (`bugleBoardEnabled`) |
|---|---|---|
| 모집글 출처 | 디스코드에서 길드원이 `/파티모집`으로 올린 글 | 게임 안 거대한 외침의 뿔피리(거뿔) `#` 모집 외침 |
| 대상 | 우리 길드원끼리 | 게임 서버 전체 |
| 자동 동작 | 매일 07시 10일 지난 스레드 정리, 출발 10분 전 참가자 DM | 최근 5건 보드 10초마다 갱신 + `/파티알림` 키워드 DM |
| 데이터 | 디스코드 메시지 | 넥슨 오픈 API |

### 설명 문구 통일
같은 틀(출처 → 보는 곳 → 자동으로 해주는 일)로 설정 명령 설명·`/섯다라인설정 목록`·안내 메시지를 맞춘다(§8 카탈로그에서 한 번만 정의).
- 🧑‍🤝‍🧑 파티모집: 길드원이 `/파티모집`으로 올린 **디스코드 모집글**을 관리해요. 오래된 글 정리 + 출발 10분 전 참가자 DM
- 📢 인게임파티모집현황: **게임 안 거뿔**의 파티모집 외침을 채널에 실시간으로 띄워요. 켜면 `/파티알림` 키워드 DM도 동작해요.

현재 어긋난 곳: 설정 명령 설명("디스코드 파티모집 자동관리(스레드 정리·출발 알림)") vs `목록`("파티모집 글 자동작성·오래된 글 정리·출발 10분전 알림"), 인게임파티모집현황도 "거뿔 파티모집 보드 게시" vs "인게임 내 거뿔 파티모집 실시간 게시".

### `/파티알림` 꺼짐 경고
- 문제: `/파티알림` 키워드 DM은 **그 서버에서 인게임파티모집현황이 켜져 있어야만** 동작한다(`events/ready/cronJob.js`에서 `bugleBoardEnabled` 확인). 그런데 `/파티알림 등록`은 이를 확인하지 않고 "DM으로 알려줄게~"라고 답한다 → 꺼진 서버에선 등록해도 **알림이 영영 오지 않고 이유도 알 수 없다.**
- 개선(기본안): `/파티알림 등록`·`목록` 응답에서 인게임파티모집현황이 꺼져 있으면 경고 표시.
  > ⚠️ 이 서버는 **인게임파티모집현황**이 꺼져 있어서 키워드 알림이 오지 않아요. 관리자에게 `/섯다라인설정 인게임파티모집현황`을 켜 달라고 요청해 주세요.
- 대안: 키워드 알림을 인게임파티모집현황과 분리해 별도 on/off(설정 항목이 하나 늘어남).

## 6. 게임서버 설정 (신규)

### 문제
거뿔 조회(`events/ready/cronJob.js`, 인게임파티모집현황·`/파티알림`)와 튼주(`commands/sturdyPocketList.js`)가 `server_name=하프`로 하드코딩. 다른 서버 길드가 인게임파티모집현황을 켜면 **자기 서버가 아닌 하프 서버 모집**이 올라온다.

### 설계
- `/섯다라인설정 게임서버 서버:<선택>` 추가 → `guildSettings`에 `gameServer` 저장.
- **미설정 시 `하프`** → 기존 서버 동작 변화 없음.
- 선택지는 넥슨 오픈 API의 `server_name` 허용값으로 고정 choices(구현 시 API 문서·실제 응답으로 확인).
- `/섯다라인설정 목록`과 안내 메시지(인게임 연동 첫 항목)에 표시.

### 영향 범위
- **인게임파티모집현황 보드**: 지금은 거뿔을 1회 조회해 모든 길드에 같은 내용 게시 → 켠 길드들의 서버별로 묶어 **서버당 1회 조회**(10초 주기 API 호출 수 = 사용 중인 서버 수).
- **`/파티알림`**: 키워드마다 등록한 길드의 서버 거뿔과 매칭.
- **`/튼주`**: 실행한 길드의 서버로 조회.
- 표시 문구: 보드·알림 푸터의 "하프서버 거뿔" → 실제 서버명.

## 7. 구현 메모

- **상태 저장**: `static/json/onboarding.json` — `{ [guildId]: { sentAt, via: 'dm' | 'channel' | 'failed' } }`. `readAll/writeAll` 관례, 파일 없으면 `{}`. 기록이 있으면 다시 보내지 않는다(실패도 기록 → 재시도 안 함).
- **신규 설치**: `events/guildCreate/registerNewGuild.js`에서 발송(기존 제작자 알림 유지). `guildCreate`는 실제 합류 시에만 발생하므로 재기동 시 중복 없음.
- **기존 서버 1회 발송 — 제작자 수동 트리거**
  - 기존 `!메세지삭제`(`events/messageCreate/bulkDelete.js`) 같은 접두사 텍스트 명령으로, **`developerId` 본인 + `devGuildId` 서버 채널에서만** 동작. 슬래시 명령으로 만들면 다른 서버 관리자에게도 보이므로 텍스트 명령이 적합. (봇 DM으로 받으면 모드메일과 겹치므로 DM은 쓰지 않음)
  - `!안내발송 미리보기`: 발송 대상 서버 수·목록(이미 기록된 서버 제외)과, 대표 서버 1곳 기준 실제 메시지를 제작자에게 DM으로 보여줌. 실제 발송 없음.
  - `!안내발송 실행`: 대상 서버에 서버당 2~3초 간격 순차 발송(DM 레이트리밋·스팸 탐지 회피). 보낼 때마다 즉시 기록 → 도중 재기동돼도 다시 실행하면 남은 서버만 보냄.
  - 끝나면 결과 요약(DM 성공 N · 채널 대체 M · 실패 K)을 제작자 DM 또는 `logChannelId`로.
  - development에서는 `getDevGuildId()` 서버만 대상.
- **버튼**: `📋 현재 설정 보기` 하나. DM 버튼엔 서버 정보가 없으므로 customId에 guildId 포함. 예: `{"action":"onboarding","op":"settings","g":"<guildId>"}` → JSON이므로 `events/interactionCreate/buttonReaction.js` switch에 action 추가. `목록`과 같은 내용 응답(누른 사람이 그 서버 서버장·관리자인지 확인).
- **받는 사람**: 기본 서버장. (선택) 봇에 감사 로그 보기 권한이 있으면 "봇 추가" 기록으로 실제 설치자 확인 가능.
- **효과 측정**: 설정 변경 시 제작자 DM(`notifyDeveloper`)이 이미 있어 "안내 발송 → 기능 켬"을 확인할 수 있다.

## 8. 기능 카탈로그 (단일 출처)

설명이 곳곳에서 어긋나는 문제를 막기 위해 설정 기능 메타데이터를 한 모듈로 모은다(예: `modules/featureCatalog.js`).

```js
{ key: 'dailyMissionEnabled', name: '오늘의미션', emoji: '📅',
  oneLine: '매일 아침 미션·베테랑 자동 게시',
  example: '/섯다라인설정 오늘의미션 상태:켜기 채널:#공지',
  section: 'ingame',   // admin(서버 관리) | ingame(인게임 연동)
  order: 2,            // 섹션 내 순서
  caution: null }      // 예: 자동삭제 → '메시지가 지워져요'
```

사용처: 1회 안내(신규·기존), `/섯다라인설정 목록`(§9), 안내 메시지의 `📋 현재 설정 보기` 버튼, `/섯다라인설정` 하위 명령 설명. 새 설정 기능을 추가할 때 카탈로그에 한 줄 추가하면 어느 섹션 몇 번째로 안내·표시될지까지 결정된다.

## 9. `/섯다라인설정 목록` 섹션 개편

### 현재(`main` `c320f39`)
한 줄로 10개 항목이 나열된다. 문제점:
- 서버 관리용과 게임 관련 설정이 섞여 있어 훑어보기 어렵다.
- 표시 이름이 실제 하위 명령 이름과 다르다(`손님권한 자동부여` ↔ `손님권한부여`, `파티모집(자동관리)` ↔ `파티모집`, `오늘의미션 게시` ↔ `오늘의미션`) → 목록을 보고 바로 명령을 칠 수 없다.
- 설명이 설정 명령 설명·안내 문구와 다르다(예: 파티모집 "글 자동작성").
- 서로 의존하는 설정의 관계가 안 보인다(승인권한부여는 감사로그가 꺼져 있으면 버튼이 안 뜸, `/파티알림`은 인게임파티모집현황이 꺼져 있으면 동작 안 함).

### 개편안
안내 메시지와 **같은 섹션·같은 순서·같은 이름**(§4, §8 카탈로그)으로 임베드 2장에 나눠 보여준다.

- 줄 형식: `상태 이름 · 값 — 설명` — 운영진이 가장 먼저 찾는 켜짐/꺼짐과 지정값을 앞에.
- 표시 이름 = 하위 명령 이름 그대로(복사해서 `/섯다라인설정 <이름>`으로 바로 사용).
- 값만 있는 설정(관리자역할·기본채널·게임서버)은 🟢/🔴 대신 고유 이모지.
- 의존 관계 경고를 해당 줄 아래에 표시.
- 푸터: `바꾸려면 /섯다라인설정 <항목이름>`

```
⚙️ <서버명> 설정

[임베드 1 — 🛠️ 서버 관리]
👑 관리자역할 · 미지정 — 서버장·제작자만 관리
#️⃣ 기본채널 · 미지정 — 명령어 친 채널에 게시
🚪 입장 관리
🟢 손님권한부여 · @손님 — 입장한 사람에게 손님 역할 자동 지급
🟢 감사로그 · #역할감사 — 입장·퇴장·역할변경 로그
🔴 승인권한부여 · @길드원 — 입장 로그 버튼으로 운영진이 확인 후 정식 역할 지급
🔴 주간랭킹 — 매주 디스코드 채팅·음성 순위
🔴 자동삭제 — 지정 채널 메시지를 설정 시간 뒤 자동 삭제

[임베드 2 — 🎮 인게임 연동]
🌐 게임서버 · 하프(기본값)
🔴 오늘의미션 — 매일 아침 오늘/내일 미션·베테랑 게시
🔴 파티모집 — 길드원이 /파티모집 으로 올린 디스코드 모집글 관리
🔴 인게임파티모집현황 — 게임 안 거뿔 모집 실시간 게시 (+ /파티알림)
💡 파티모집과 인게임파티모집현황은 서로 다른 기능이에요

바꾸려면 /섯다라인설정 <항목이름>
```

의존 관계 경고(해당 조건일 때만 줄 아래에 표시):
- 승인권한부여 켜짐 + 감사로그 꺼짐 → `⚠️ 감사로그가 꺼져 있어 승인 버튼이 안 떠요`
- 인게임파티모집현황 꺼짐 + 이 서버에 `/파티알림` 등록자 있음 → `⚠️ 길드원 N명이 /파티알림을 등록했지만 꺼져 있어 알림이 안 가요`
- 승인권한부여 역할 = 손님권한부여 역할 → `⚠️ 승인 후 주는 역할이 손님 역할과 같아요` (하위호환으로 남은 옛 값일 가능성)

구현 메모:
- 임베드 필드 값은 1024자 제한이 있어 자동삭제 채널이 많으면 넘칠 수 있다 → 섹션별 임베드의 description(4096자)에 줄을 쓰는 방식 권장.
- 안내 메시지의 `📋 현재 설정 보기` 버튼도 같은 빌더를 재사용.

## 10. 작업 순서(권장)

1. 게임서버 설정(§6) — 안내 메시지·목록에 포함되므로 먼저
2. 파티 기능 설명 통일 + `/파티알림` 경고(§5)
3. 기능 카탈로그(§8) + `/섯다라인설정` 설명 연결 + `목록` 섹션 개편(§9)
4. 안내 메시지 빌더(카탈로그 + 서버별 ✅) + 신규 설치 발송
5. 배포 → dev 서버에서 `!안내발송 미리보기`로 확인 → `!안내발송 실행` 1회
