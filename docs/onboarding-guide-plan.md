# 설치 후 기능 안내 + 파티 기능 정리 (기획 확정·미구현)

> 상태: 기획, 구현 대기. "기본안"으로 표시된 항목은 구현 전 최종 확인.
> 기준 코드: `main` `f2b6d0b`

## 1. 배경

- 봇이 새 서버에 들어가면(`events/guildCreate/registerNewGuild.js`) **제작자에게만** 설치 DM이 가고, 서버장에게는 아무 안내가 없다.
- `/섯다라인설정`의 기능은 **기본이 전부 꺼짐**이고 관리자만 켤 수 있다. 서버장이 모르면 길드원 눈엔 존재 자체가 안 보인다.
  → 기능을 "안 쓴다"기보다 "켜야 하는 줄 모른다"에 가깝다.
- 서버장 신원(`guildRegistry.json`의 `ownerId`)과 기능 on/off(`guildSettings.json`)가 이미 저장돼 있어 대상 판별이 가능하다.
- 일반 명령어(`/오미`, `/요리` 등 21개)는 설치 즉시 동작하고 `/`나 `/섯다라인`(명령어 목록 자동 생성)으로 스스로 발견된다.

## 2. 원칙

- **안내 대상은 설정 기능(`/섯다라인설정`)만.** 일반 사용자용 명령어는 안내하지 않는다.
- **서버당 딱 1회 발송, 반복·리마인드 없음.** 한 번 보낸 서버엔 다시 보내지 않는다.
- 1회뿐이므로 `🔕 다시 받지 않기` 버튼은 두지 않는다.

이유: 서버장은 DM 수신에 동의한 적이 없어 반복 DM은 광고로 느껴지고, 봇 계정이 스팸 신고·탐지 대상이 되면 전체 서버의 봇이 함께 멈출 수 있다. 설정 기능 전체를 한 번에 제대로 안내하면 반복할 필요가 없다.

## 3. 발송 대상과 시점

| 대상 | 시점 | 받는 곳 | 내용 |
|---|---|---|---|
| **기존 설치 서버** | 이 기능 배포 시 1회(일괄) | 서버장 DM → 실패 시 서버 시스템 채널 | §4 섹션별 전체 안내 + **이미 켠 기능 ✅ 표시** + 파티 기능 이름 변경 공지(§5) |
| **신규 설치 서버** | 설치 직후 1회 | 서버장 DM → 실패 시 서버 시스템 채널 | §4 섹션별 전체 안내 |

- 기존 서버 안내는 이번 개편(파티 기능 이름 변경·설명 정리)의 공지도 겸하므로, 기능을 이미 켠 서버에도 보낸다. 켜 둔 기능은 ✅ 표시로 구분해 "이미 쓰는 기능 + 아직 안 쓰는 기능"을 한눈에 보여준다.
- 특히 기존 `파티모집`·`인게임파티모집현황`을 켜 둔 서버엔 "설정 명령 이름이 `길드파티모집`·`거뿔파티중계`로 바뀌었어요(설정은 그대로 유지)" 한 줄을 추가.
- DM 실패 시 시스템 채널 대체도 서버당 1회뿐이라 허용. 시스템 채널도 없거나 권한이 없으면 실패로 기록하고 끝.

## 4. 안내할 설정 기능 — 섹션별 전체 안내

서버 관리용 설정(감사로그·손님권한부여·기본채널·자동삭제)도 중요하므로 **1회 안내에서 설정 기능 전체를 한 번에** 안내한다. 길이 부담은 섹션으로 나눠 해결한다.

### 섹션 구성

| 섹션 | 성격 | 기능 |
|---|---|---|
| 🛠️ 서버 관리 | 디스코드 서버 운영(권한·입장·채널 정리·활동) | 관리자역할, 기본채널, 손님권한부여, 감사로그, 주간랭킹, 자동삭제 |
| 🎮 인게임 연동 | 마비노기 모바일 게임 정보·파티 | 오늘의미션, 길드파티모집, 거뿔파티중계 |

- 주간랭킹은 게임이 아닌 디스코드 채팅·보이스 활동 기반이라 "서버 관리"(길드원 활동 파악)에 둔다.
- 길드파티모집은 디스코드 안 기능이지만 게임 파티가 목적이고, 거뿔파티중계와 나란히 비교해야 헷갈리지 않으므로(§5) "인게임 연동"에 둔다.

### 섹션 내 순서와 문구

순서 원칙: **설정 순서(선행 조건) → 흐름으로 묶이는 기능은 붙여서 → 주의 기능은 마지막**

🛠️ 서버 관리

| # | 기능 | 한 줄 소개 | 설정 예시 |
|---|---|---|---|
| 1 | 👑 관리자역할 | 운영진에게 봇 설정 권한 넘기기(서버장만 지정 가능) | `/섯다라인설정 관리자역할 역할:@운영진` |
| 2 | #️⃣ 기본채널 | 명령어 결과를 한 채널에 모아 올려 채팅 채널을 깔끔하게 | `/섯다라인설정 기본채널 채널:#봇` |
| 3 | 🙋 손님권한부여 | 입장한 사람에게 손님 역할 자동 지급 | `/섯다라인설정 손님권한부여 상태:켜기 역할:@손님` |
| 4 | 🛡️ 감사로그 | 입장(승인 버튼)·역할 변경·퇴장 기록을 한 채널에 | `/섯다라인설정 감사로그 상태:켜기 채널:#로그 승인역할:@길드원` |
| 5 | 🏆 주간랭킹 | 매주 디스코드 채팅·보이스 활동 순위 게시 | `/섯다라인설정 주간랭킹 상태:켜기 채널:#랭킹` |
| 6 | 🧹 자동삭제 | 지정 채널 메시지를 N분 뒤 자동 삭제(핀 제외) **⚠️ 메시지가 지워지니 채널을 확인하고 켜기** | `/섯다라인설정 자동삭제 상태:켜기 채널:#봇명령 분:10` |

- 3·4는 **입장 관리 흐름**으로 묶어 소개: 입장 → 손님 역할 자동 지급 → 로그 채널의 승인 버튼 → 길드원 역할.

🎮 인게임 연동

| # | 기능 | 한 줄 소개 | 설정 예시 |
|---|---|---|---|
| 1 | 📅 오늘의미션 | 매일 아침 오늘·내일 미션과 베테랑 던전 자동 게시 | `/섯다라인설정 오늘의미션 상태:켜기 채널:#공지` |
| 2 | 🏠 길드파티모집 | 길드원이 `/파티모집`으로 올린 디스코드 모집글 관리(오래된 글 정리·출발 10분 전 DM) | `/섯다라인설정 길드파티모집 상태:켜기 채널:#파티모집` |
| 3 | 📯 거뿔파티중계 | 게임 안 거뿔 모집 외침을 실시간 중계 + `/파티알림` 키워드 DM | `/섯다라인설정 거뿔파티중계 상태:켜기 채널:#거뿔` |

- 2·3은 "💡 둘은 다른 기능이에요 — 디스코드 모집글 vs 게임 안 거뿔" 한 줄과 함께 붙여서 소개.

## 5. 파티 기능 2종 정리

### 현재 차이

| | 파티모집 (`partyRecruitEnabled`) | 인게임파티모집현황 (`bugleBoardEnabled`) |
|---|---|---|
| 모집글 출처 | 디스코드에서 길드원이 `/파티모집`으로 올린 글 | 게임 안 거대한 외침의 뿔피리(거뿔) `#` 모집 외침 |
| 대상 | 우리 길드원끼리 | 게임 서버 전체 |
| 자동 동작 | 매일 07시 10일 지난 스레드 정리, 출발 10분 전 참가자 DM | 최근 5건 보드 10초마다 갱신 + `/파티알림` 키워드 DM |
| 데이터 | 디스코드 메시지 | 넥슨 오픈 API |

### 헷갈리는 이유
1. 이름의 핵심 단어("파티모집")가 같아 **모집글의 출처**가 드러나지 않는다.
2. 같은 기능의 설명이 설정 명령·`목록`에서 서로 다르다("거뿔" 약어 포함).
3. `/파티알림`은 이름상 `/파티모집` 쪽처럼 보이지만 **인게임파티모집현황이 켜져 있어야만** 동작하고, 꺼진 서버에서 등록해도 아무 경고가 없다(알림이 영영 안 옴).
4. `/섯다라인설정 파티모집`은 "채널 지정 + 자동관리 켜기"인데, `/파티모집` 명령은 채널만 있으면 자동관리가 꺼져도 동작한다.

### 개선
- **표시 이름 변경(기본안 A)**: 파티모집 → **길드파티모집**, 인게임파티모집현황 → **거뿔파티중계**. 설정 키는 그대로 유지(마이그레이션 불필요). 설정 하위 명령 이름이 바뀌므로 공지 필요.
- **설명 문구 통일**: 출처 → 보는 곳 → 자동으로 해주는 일
  - 🏠 길드파티모집: 길드원이 `/파티모집`으로 올린 **디스코드 모집글**을 관리해요. 오래된 글 정리 + 출발 10분 전 참가자 DM
  - 📯 거뿔파티중계: **게임 안 거뿔**의 파티모집 외침을 채널에 실시간으로 띄워요. 켜면 `/파티알림` 키워드 DM도 동작해요.
- **`/파티알림` 의존성(기본안 ①)**: `/파티알림 등록`·`목록`에서 거뿔파티중계가 꺼져 있으면 "⚠️ 이 서버는 거뿔파티중계가 꺼져 있어 알림이 오지 않아요. 관리자에게 요청해 주세요" 표시.
  - 대안 ②: 키워드 알림을 거뿔파티중계와 분리해 별도 on/off.
- **게임 서버 고정 문제(미정)**: 거뿔 조회(`events/ready/cronJob.js`)와 튼주(`commands/sturdyPocketList.js`)가 `server_name=하프`로 하드코딩. 하프 외 서버 길드가 있으면 `/섯다라인설정 게임서버` 추가 필요.

## 6. 기능 카탈로그 (단일 출처)

설명이 곳곳에서 어긋나는 문제를 막기 위해 설정 기능 메타데이터를 한 모듈로 모은다(예: `modules/featureCatalog.js`).

```js
{ key: 'dailyMissionEnabled', name: '오늘의미션', emoji: '📅',
  oneLine: '매일 아침 미션·베테랑 자동 게시',
  example: '/섯다라인설정 오늘의미션 상태:켜기 채널:#공지',
  section: 'ingame',   // admin(서버 관리) | ingame(인게임 연동)
  order: 1,            // 섹션 내 순서
  caution: null }      // 예: 자동삭제 → '메시지가 지워져요'
```

사용처: 1회 안내(기존·신규), `/섯다라인설정 목록`(같은 섹션 구조로 묶어 표시), `/섯다라인설정` 하위 명령 설명. 새 설정 기능을 추가할 때 카탈로그에 한 줄 추가하면 어느 섹션 몇 번째로 안내될지까지 결정된다.

## 7. 구현 메모

- **상태 저장**: `static/json/onboarding.json` — `{ [guildId]: { sentAt, via: 'dm' | 'channel' | 'failed' } }`. `readAll/writeAll` 관례, 파일 없으면 `{}`. 기록이 있으면 다시 보내지 않는다(실패도 기록 → 재시도 안 함).
- **신규 설치**: `events/guildCreate/registerNewGuild.js`에서 발송(기존 제작자 알림은 유지). `guildCreate`는 실제 합류 시에만 발생하므로 재기동 때 중복 발송 없음.
- **기존 서버 일괄 발송**: `events/ready/`에 1회성 핸들러(예: `onboardingBroadcast.js`).
  - 대상: 봇이 들어가 있는 길드 중 `onboarding.json`에 기록이 없는 서버. 받는 사람은 `guild.ownerId`(registry 백필과 병렬 실행되므로 registry에 의존하지 않음).
  - **발송 기한 상수(`BROADCAST_UNTIL`, 예: 배포일 + 7일)**: 이 날짜가 지나면 일괄 발송 로직은 아무것도 안 한다. `onboarding.json`은 gitignore·머신별이라 VM 재구축 등으로 유실되면 전 서버에 재발송될 수 있는데, 기한이 이를 막는다.
  - 한 번에 몰아 보내지 않고 서버당 2~3초 간격으로 순차 발송(DM 레이트리밋·스팸 탐지 회피). 발송 후 즉시 기록 → 도중에 재기동돼도 보낸 서버는 건너뜀.
  - 끝나면 결과 요약(DM 성공 N · 채널 대체 M · 실패 K)을 제작자 DM 또는 `logChannelId`로.
  - development에서는 `getDevGuildId()` 서버만 대상(실제 서버장에게 테스트 발송 금지).
- **버튼**: `📋 현재 설정 보기` 하나. DM 버튼엔 서버 정보가 없으므로 customId에 guildId 포함. 예: `{"action":"onboarding","op":"settings","g":"<guildId>"}` → JSON이므로 `events/interactionCreate/buttonReaction.js` switch에 action 추가. `목록`과 같은 내용을 응답(누른 사람이 그 서버의 서버장·관리자인지 확인).
- **받는 사람**: 기본 서버장. (선택) 봇에 감사 로그 보기 권한이 있으면 "봇 추가" 기록으로 실제 설치자 확인 가능.
- **효과 측정**: 설정 변경 시 제작자 DM(`notifyDeveloper`)이 이미 있으므로 "안내 발송 → 기능 켬" 전환을 확인할 수 있다.

## 8. 작업 순서(권장)

1. 파티 기능 정리(이름·설명 통일·`/파티알림` 경고) — 안내 문구가 이 이름을 쓰므로 먼저
2. 기능 카탈로그 모듈 + `/섯다라인설정` 설명·`목록` 연결
3. 안내 메시지 빌더(카탈로그 + 서버별 켜짐 ✅ 표시) + 신규 설치 발송
4. 기존 서버 1회 일괄 발송(기한 상수·순차 발송·결과 요약) — 1~3과 **같은 배포**에 포함해야 이름 변경 공지가 맞물린다

## 9. 데이터로 우선순위 보정(선택)
