# 섯다라인 소식 구독 (동의 기반 DM 뉴스) (기획·미구현)

> 상태: 기획, 구현 대기. "기본안"은 구현 전 확인.
> 기준 코드: `main` `18fb017`(봇·`addon_server/`), 애드온 `833b388`. 관련 기획: `docs/onboarding-guide-plan.md`(설정 1회 안내), `docs/support-server-spotlight-plan.md`(섯다라인 서버 주간 소개)

## 1. 목적

봇을 설치한 사람(서버장)에게 **"섯다라인 소식을 받아 보시겠어요?"를 먼저 묻고**, **예**를 누른 사람에게만 소식 DM을 보낸다.

- 섯다라인 서버에 초대하지 않아도 설치한 사람은 `guild.ownerId`로 알 수 있다.
- 동의를 받고 보내므로 스팸이 아니다. 묻지 않고 반복 발송하던 이전 아이디어의 문제(동의 없음)를 해결한다.

## 2. 묻기

### 질문 메시지

```
📰 섯다라인 소식을 받아 보시겠어요?

새 기능·큰 업데이트가 있을 때 DM으로 알려 드려요. (월 1~2회 정도)
언제든 소식 메시지의 [그만 받기] 버튼으로 끌 수 있어요.

[🔔 받을게요]  [🔕 괜찮아요]
```

- **보낼 양과 주기를 질문에 적는다** — 무엇에 동의하는지 알아야 "예"를 누르기 쉽다.
- **첫 질문은 설정 1회 안내 메시지에 붙인다**(신규 설치 직후 / 기존 서버 일괄 1회). 질문을 위한 DM을 따로 늘리지 않는다.
  - 안내 메시지 버튼: `[📋 현재 설정 보기]` + `[🔔 소식 받기]` `[🔕 괜찮아요]`
- DM이 막혀 시스템 채널로 대신 올라간 안내에는 질문 버튼을 붙이지 않는다(공개 채널에서 누구나 누를 수 있으므로). 이 경우 재질문도 하지 않는다.

### 무응답 재질문 (최대 2번 더)

| 회차 | 시점 | 내용 |
|---|---|---|
| 1 | 설정 1회 안내와 함께 | 안내 + 질문 버튼 |
| 2 | 1회차 후 7일, 무응답일 때 | 질문만 짧게(설정 안내 반복 안 함) |
| 3 | 2회차 후 21일, 무응답일 때 | 질문만 + "마지막으로 여쭤봐요" |
| 이후 | — | 다시 묻지 않음(무응답 = 안 받음으로 처리) |

- **예/아니오 중 하나라도 누르면 즉시 끝**, 다시 묻지 않는다.
- 재질문 메시지는 짧게 — 소식 질문 한 줄 + 버튼.
- 봇이 그 서버에서 나갔거나(`guildDelete`) 서버장이 바뀌면 재질문 중단.

### 사람 단위로 묻기
한 사람이 서버를 여러 개 갖고 있을 수 있으므로 **서버가 아니라 사람(userId) 단위**로 한 번만 묻는다. 두 번째 서버에 설치해도 이미 답한 사람이면 묻지 않는다.

## 3. 소식 보내기

### 무엇을, 얼마나 자주
- 기본안: **새 기능·큰 업데이트만, 월 1~2회.** 섯다라인 서버의 주간 기능 소개(주 1회)는 DM으로 보내기엔 잦으므로 포함하지 않는다.
- 모든 소식 DM에 **`[🔕 그만 받기]` 버튼** — 누르면 즉시 구독 해제, 확인 응답만 보내고 끝.
- 소식 DM 하단에 섯다라인 서버 초대 링크(문의·아이디어).

### 작성·발송 흐름 (기본안: 공지 채널 연동)
글은 한 곳에서만 쓴다: **섯다라인 서버의 공지 채널에 제작자가 올린 글 = 소식**.
1. 제작자가 공지 채널에 글을 올린다.
2. 봇이 그 글에 **제작자만 보이는 확인**(제작자 DM으로 "구독자 N명에게 보낼까요? [보내기] [안 보내기]")을 띄운다. 모든 공지가 DM 감은 아니므로 자동 발송하지 않는다.
3. [보내기] → 구독자에게 순차 발송(사람당 2~3초 간격, DM 레이트리밋·스팸 탐지 회피). 끝나면 결과 요약(성공 N · DM 막힘 M).
- DM이 막힌 구독자는 기록해 두고 3회 연속 실패 시 구독 해제(보낼 수 없는 대상 정리).

대안: `!소식발송` 제작자 텍스트 명령(테스트 서버 전용, `!안내발송`과 같은 방식).

## 4. 구현 메모

- **상태 저장**: `static/json/newsSubscribers.json`
  ```json
  { "<userId>": { "status": "pending|yes|no|expired", "asked": ["2026-11-12", ...],
                  "guilds": ["<guildId>"], "dmFail": 0 } }
  ```
  `readAll/writeAll` 관례, 없으면 `{}`.
- **첫 질문**: 설정 1회 안내 빌더에 버튼 추가(onboarding 기획 §4·§7). DM으로 보낸 경우에만 `pending` + `asked[0]` 기록.
- **재질문**: `events/ready/cronJob.js`에 하루 1회 잡(저녁 KST) — `pending`이고 마지막 질문 후 7일/21일 지난 사람에게. 3회 질문 후 무응답이면 `expired`. development에선 테스트 서버 서버장만.
- **버튼**: JSON customId → `events/interactionCreate/buttonReaction.js` switch에 `action: 'news'` 추가. `op: 'yes'|'no'|'stop'`. DM 버튼이라 누른 사람 = `interaction.user.id`로 판별(서버 정보 불필요).
  - 누르면 버튼을 비활성화한 메시지로 수정 + "알겠어요! …" 짧은 응답.
- **공지 연동**: `events/messageCreate/`에 핸들러 — `config/bot.js`의 `newsChannelId`(섯다라인 서버 공지 채널) + 작성자 `developerId`일 때만 제작자 DM으로 발송 확인.
- **설정 1회 안내 기획과의 관계**: 설정 안내 자체는 여전히 서버당 1회(리마인드 없음). 재질문 2번은 **소식 구독 질문만** 짧게 보낸다.

## 5. 애드온 사용자도 묻기

봇만 쓰는 사람(서버장)과 애드온만 쓰는 사람이 따로 있으므로, **애드온 앱 안에서도** 소식을 받을지 묻는다. 애드온 사용자는 디스코드 로그인을 안 했을 수도 있으므로 **앱 안에서 받는 것이 기본**, 로그인한 사람만 DM을 추가로 고를 수 있다.

### 앱에서 묻기
```
📰 섯다라인 소식을 받아 보시겠어요?
새 기능 소식과 사용 팁을 앱에서 알려 드려요. (새 기능은 월 1~2회, 팁은 주 1회 홈 화면에)
[🔔 받을게요]  [🔕 괜찮아요]
☐ 디스코드 DM으로도 받기   ← 디스코드 로그인한 경우에만 보임
```
- **첫 실행 때는 묻지 않는다**(첫 실행은 온보딩 투어·영역 지정으로 바쁨). 기본안: 3번째 실행 또는 설치 3일 후 중 늦은 때, 홈 화면 카드로.
- 무응답 재질문 규칙은 봇과 같음(7일 후, 그 후 21일 후, 총 3번). 앱이 켜져 있을 때만 셈.
- 답은 앱 로컬 설정에 저장. 로그인한 경우 애드온 서버에도 저장(다른 PC에서 다시 묻지 않게).

### 앱에서 받는 내용
| 종류 | 표시 | 주기 |
|---|---|---|
| 🆕 새 기능·큰 업데이트 | 토스트 알림 1번 + 홈의 "소식" 목록 | 월 1~2회 |
| 💡 사용 팁 | 홈 화면 카드(토스트 없음) — "혹시 이 기능 써 보셨나요?" | 주 1회 |

- 사용 팁은 섯다라인 서버 주간 소개의 **애드온 소개 목록**(`docs/support-server-spotlight-plan.md` §8)을 재사용. 이미 켜 둔 기능은 앱이 알 수 있으므로 건너뛴다(앱 안이라 가능한 개인화).
- 애드온 자체 업데이트 노트(새 버전 첫 실행 시 뜨는 `release_notes.md`)는 기존대로 유지 — 소식과 겹치는 내용이면 소식 쪽은 "업데이트 노트 보기"로 연결.
- 소식을 "괜찮아요"한 사람에게도 업데이트 노트는 그대로 뜬다(앱 기능의 일부).

## 6. 봇·애드온 통합 발송

### 소식 대상 표시
제작자가 공지 채널 글을 소식으로 보낼 때 대상을 고른다: `[🤖 봇] [🖥️ 애드온] [📣 공통]`

| 받는 사람 | 받는 소식 | 경로 |
|---|---|---|
| 봇 설치자(서버장)만 | 🤖봇 + 📣공통 | 디스코드 DM |
| 애드온 사용자만 | 🖥️애드온 + 📣공통 | 앱 안(+ DM 선택 시 DM) |
| 둘 다 | 전부 | DM은 **한 사람당 소식 1통**(디스코드 ID로 중복 제거) |

### 흐름
```
제작자: 섯다라인 서버 공지 채널에 글 작성
  → 봇: 제작자 DM "소식으로 보낼까요? 대상 [봇][애드온][공통] / [안 보내기]"
  → 대상 선택 시
     ① DM 구독자(봇 설치자 yes ∪ 애드온 DM 선택자, 대상 맞는 사람, 디스코드 ID 중복 제거)에게 순차 DM
     ② 애드온 서버에 소식 등록 → 앱이 가져가 앱 안에 표시
```

### 애드온 서버 쪽(이 저장소 `addon_server/`)
- `news` 테이블: `id, created, target(bot|addon|all), title, body, url`.
- `GET /news?since=<id>` — **인증 없음**(로그인 안 한 사용자도 받음). 앱이 시작할 때와 켜진 동안 하루 1번 호출. 대상이 `addon`·`all`인 것만.
- `users`에 `news_pref`(`none|app|dm`) 추가 + `PUT /me/news-pref`(로그인 사용자).
- 봇 → 소식 등록: `POST http://127.0.0.1:8000/admin/news`(같은 VM 내부 호출, `addon_server/.env`의 내부 키로 인증, Caddy 밖으로 노출 안 함).
- 봇 → DM 대상 조회: 애드온 DB를 읽기 전용으로 열어 `news_pref='dm'` 사용자 목록(README 1.4의 "봇이 읽기 전용으로 열 수 있음" 경로).

### 애드온 앱 쪽 (`StarlineBot/mabinogi_addon` — 이 저장소 밖, 해당 저장소 기획으로 옮길 것)
- 홈 화면 소식 질문 카드 + 재질문 규칙, 로컬 저장, 로그인 시 서버 저장.
- `GET /news` 폴링, 새 기능 소식 토스트(기존 `ui/toast.py`), 홈 "소식" 목록, 사용 팁 카드(켜 둔 기능 제외).
- 화면은 애드온 저장소 규칙대로 먼저 렌더해 확인받기(`CLAUDE.md` "화면(UI) 개발").

## 7. 결정 현황

| 항목 | 결정 |
|---|---|
| 방식 | **확정**: 설치한 사람에게 소식 수신 여부를 묻고 "예"만 발송 |
| 무응답 | **확정**: 1~2번 더 묻기 → 기본안: 7일 후, 그 후 21일 후(총 3번) 이후 중단 |
| 첫 질문 위치 | 기본안: 설정 1회 안내 메시지에 버튼으로 |
| 소식 내용·주기 | 기본안: 새 기능·큰 업데이트, 월 1~2회 |
| 작성·발송 | 기본안: 섯다라인 서버 공지 채널 글 → 제작자 확인 → 구독자 DM |
| 질문 단위 | 기본안: 사람(userId) 단위 1번 |
| 애드온 사용자 | **확정 방향**: 앱 안에서도 묻기, 앱 안 수신이 기본 + 로그인 시 DM 선택 |
| 앱 질문 시점 | 기본안: 3번째 실행 또는 설치 3일 후 중 늦은 때, 홈 카드 |
| 앱 수신 내용 | 기본안: 새 기능(토스트+소식 목록, 월 1~2회) + 사용 팁(홈 카드, 주 1회, 켜 둔 기능 제외) |
| 소식 대상 | 기본안: 발송 시 [봇][애드온][공통] 선택, DM은 사람당 1통 |
